# 🏛️ 워크스페이스 최상위 행동 지침 (Law.md)

본 문서는 `AI Agent` 워크스페이스에서 작동하는 모든 AI 에이전트(Antigravity/Gemini CLI, OpenAI Codex, Claude Code 등)가 **모든 작업 수행 이전에 반드시 읽고 최우선으로 준수해야 하는 절대적인 헌법(Constitution)**입니다.

---

## 제0조 [용어의 정의]

1. **메인지침**: 워크스페이스 최상위 루트 디렉터리에 위치한 [Law.md](file:///C:/Users/USER/OneDrive/바탕%20화면/AI%20Agent/Law.md) 파일을 의미한다. 사용자가 '메인지침', '메인지침 파일', '헌법' 등을 언급할 때는 언제나 이 문서를 가리킨다.
2. **스킬(Skill)**: `Skill/` 디렉터리 및 시스템에 등록된 모듈화된 전문 작업 지침서, 런북, 자동화 스크립트 묶음(`SKILL.md`, `scripts/` 등)을 의미한다.
3. **에이전트(Agent)**: 본 워크스페이스 환경에서 사용자의 명령을 수행하고 페어 프로그래밍을 진행하는 AI 어시스턴트를 의미한다.

## 제1조 [기본 원칙과 행동 강령]

1. **사전 분석 우선 원칙 (Look Before You Leap)**
   - 코드를 생성, 수정, 삭제하기 전에 반드시 기존 파일 구조, 모듈 간 의존성, 실행 환경을 먼저 분석한다.
   - 불확실하거나 모호한 요구사항이 있을 경우 임의로 넘겨짚지 않고 반드시 사용자에게 확인을 요청한다.

2. **스킬 탐색 및 활용 계획 수립 원칙 (Skill Discovery & Planning)**
   - 사용자의 작업 요청을 받았을 때, 반드시 워크스페이스 내 [`Skill/INDEX.md`](file:///C:/Users/USER/OneDrive/바탕%20화면/AI%20Agent/Skill/INDEX.md) 및 [`Skill/`](file:///C:/Users/USER/OneDrive/바탕%20화면/AI%20Agent/Skill) 폴더(및 등록된 가용 스킬 목록)에서 해당 작업에 적용하거나 활용할 수 있는 스킬을 **모두 탐색**한다.
   - **스킬 제작/수정 요청 시**: 사용자가 새로운 스킬 생성을 요청하면(예: "자기소개서 쓰는 스킬 만들어줘" 등), 반드시 워크스페이스 내 [`Skill/skill-creator`](file:///C:/Users/USER/OneDrive/바탕%20화면/AI%20Agent/Skill/skill-creator) 메타 스킬을 활용하여 [`Skill/<신규스킬명>/`](file:///C:/Users/USER/OneDrive/바탕%20화면/AI%20Agent/Skill) 경로에 표준 규격으로 스킬을 생성하고 검증을 완료한다.
   - 탐색된 스킬들의 가이드라인과 헬퍼 스크립트, 레퍼런스를 바탕으로 **어떻게 작업을 수행할 것인지 구체적인 계획(Plan)을 먼저 수립**한 후 실행한다.

3. **최소 침습적 수정 원칙 (Minimal Invasiveness)**
   - 요구사항과 직접 관련 없는 기존 코드, 주석, 포맷팅, 파일 구조를 임의로 변경하거나 삭제하지 않는다.
   - 변경이 필요한 타깃 영역만 정확하게 수정한다.

4. **안정성 및 검증 의무 (Verification & Safety)**
   - 코드 작성 및 수정 후 구문 오류, 린트 오류, 런타임 오류가 없는지 테스트와 검증을 철저히 거친다.
   - 파일 대량 삭제, 데이터베이스 초기화, 설정 덮어쓰기 등 비가역적(파괴적) 작업은 사전에 사용자 승인을 얻어야 한다.

5. **팩트체크 및 근거 기반 검증 원칙 (Grounded Verification)**
   - 에이전트는 답변이나 코드 작성 시 단순 기억(내부 가중치/추측)에만 의존하여 답변해서는 절대 안 된다.
   - 코드 동작, 파일 내용, 라이브러리 스펙, 설정 상태 등 **검수나 팩트체크가 필요한 부분은 반드시 실제 파일 열람, 코드베이스 분석, 명령어 실행 또는 공식 문서 조회를 통해 사실 여부를 직접 확인한 후 근거를 바탕으로 답변**해야 한다.

## 제2조 [프로젝트 및 서브 시스템 구조]

본 워크스페이스는 기능별 서브 디렉터리로 분리되어 관리됩니다. 각 디렉터리의 역할과 격리성을 유지해야 합니다.

- `Skill/`
  - **역할**: 워크스페이스 전용 및 공유 스킬 패키지 관리(`skill-creator/` 등)
  - **구성**: 각 스킬별 `SKILL.md`, `scripts/`, `references/`, `assets/` 등
- `Antigravity1/`
  - **역할**: MediTime 복약 알림 및 건강 관리 풀스택 애플리케이션
  - **구성**: FastAPI 백엔드(`backend/`), 바닐라 JS/HTML 프론트엔드(`frontend/`), SQLite DB(`meditime.db`), 테스트 슈트(`tests/`), 가상환경(`.venv/`)
- `Gmail/`
  - **역할**: Gmail API 기반 이메일 수신, 파싱, 발송 자동화 워크플로우
- `NotebookLM/`
  - **역할**: 지식 베이스 구축, 리서치 소스 관리(`sources/`), NotebookLM 연동 및 동기화 스크립트
- `Stablecoin/`
  - **역할**: 국내외 스테이블코인 실시간 인텔리전스, 페깅 모니터링 및 심층 리포트/채널 연구 플랫폼
  - **구성**: Next.js App Router(`src/`), 반응형 컴포넌트(`components/`), 데이터 레이어(`data/`), 6단계 학습 모듈 및 AI 코파일럿

## 제3조 [개발 및 보안 표준]

1. **환경 격리 및 의존성 관리**
   - 각 서브 프로젝트의 가상환경(`.venv` 등)과 패키지 관리 체계(`requirements.txt`, `package.json`)를 준수하며, 시스템 전역 환경을 오염시키지 않는다.
   - 새로운 라이브러리가 필요할 경우 해당 서브 디렉터리의 의존성 파일에 기록한다.

2. **보안 및 환경 변수 관리**
   - API Key, OAuth 토큰, DB 접속 정보, 비밀번호 등의 민감 정보는 코드에 절대 하드코딩하지 않는다.
   - 모든 보안 설정은 `.env` 파일 또는 시스템 환경 변수로 관리하며, `.env`, `.git`, 인증서 파일이 외부에 노출되지 않도록 주의한다.

3. **에러 핸들링 및 복원력**
   - 외부 API 연동(Google Workspace, Gemini, OpenAI, Claude, NotebookLM 등) 시 네트워크 장애나 응답 지연에 대비한 재시도 및 예외 처리를 명확히 구현한다.

## 제4조 [커뮤니케이션 및 사용자 인터랙션]

1. **기본 언어**: 사용자의 명시적 요청이 없는 한 모든 대화와 설명은 **자연스럽고 정중한 한국어**로 작성한다.
2. **투명한 설명**: 작업 결과, 파일 변경 내역(Diff), 실행 명령어는 마크다운 코드 블록과 [파일 링크](file:///C:/Users/USER/OneDrive/바탕%20화면/AI%20Agent/Stablecoin/.agents/rules/law.md)를 활용하여 일목요연하게 전달한다.
3. **중요 의사결정**: 아키텍처 변경, 새로운 의존성 추가, 주요 알고리즘 선택 등 중요한 분기점에서는 사용자에게 옵션과 장단점을 제시하고 피드백을 구한다.
4. **철저한 팩트체크 및 근거 제시**: 답변 시 막연한 기억이나 추측에 의존하지 않고, 직접 열람하거나 검증한 파일/문서의 내용을 바탕으로 사실에 입각하여 답변한다.
